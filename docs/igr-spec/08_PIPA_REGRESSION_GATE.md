# Regressão Pipa e Base de Aprendizagem

## Estado atual: opcional, não bloqueante

O IGR **não depende de Pipa para começar**. O fluxo oficial é decisório: uma escolha aceita registra racional, responsável, fonte e, quando aplicável, atualiza uma premissa da versão de trabalho. A versão calculada gera snapshot; a aprovação congela baseline; e esse baseline passa a alimentar a biblioteca histórica interna.

O runner Pipa está implementado e validado para receber casos canônicos quando houver interesse em importar legado. Ele valida inputs, horizonte, fórmula, outputs esperados e tolerância. Entretanto, Pipa é uma fonte histórica opcional, não uma catraca que impede o Lucas de decidir e modelar um projeto novo.

| ----------------------- | ---------------------------------------------------------- | -------------------------- |
| Decisões aceitas no IGR | Fonte primária do projeto vivo.                            | Ativa.                     |
| Baseline aprovada       | Referência interna para comparação e aprendizado contínuo. | Ativa.                     |
| Seed Natal              | Exemplo honesto de conjunto pendente e rastreável.         | Ativo.                     |
| Dataset Pipa externo    | Importação histórica opcional pelo runner de regressão.    | Pronto para receber dados. |

> Não se cria “regressão Pipa” com número ilustrativo. Se o legado vier, ele entra como fonte versionada. Se não vier, o IGR aprende com as próprias decisões aprovadas — simples, limpo e sem invocar planilha morta no terreiro.
